# User Page Gift Implementation Plan

> For agentic workers: REQUIRED SUB-SKILL: Use `tx-vm-pagebacked`,
> `tx-vfs-filesystem`, `tx-implementation-readiness`, and
> `tx-xtask`. If executing the whole plan task-by-task, use
> `superpowers:subagent-driven-development` or
> `superpowers:executing-plans`.

**Status:** in progress (2026-06-05)

**Goal:** implement true `vmsplice(SPLICE_F_GIFT)` page transfer without turning
VM recipes into page-granular authoritative state.

**Architecture:** VM remains the owner of user address meaning:
`VmEntry` range recipes are authoritative, PTEs are derived materializations,
and `RangeLock` coordinates recipe/PTE mutation. Gifting descends to page
granularity only inside a VM-owned operation that returns a linear
`UserPageGift` token. Pipe stores the token as an ordered descriptor payload;
PageBacked consumes the token into a `PageContainer` entry or copies and drops
it.

**Tech stack:** `tx-subsystems` VM/PageBacked/pipe, `tx-substrate`
page-allocator typed frame evidence, `tx-shims` splice/vmsplice syscall
dispatch, active docs under `docs/design/` and `docs/Txv3/`.

## Architectural Anchors

- `docs/design/03_memory-vm/VM_v1_2.md`
  - `txdoc:VM-ADDRESS-BOUNDARY-POLICY`: VM owns user address values and
    copy/fault gates; callers must not receive raw user pointers or freeing
    authority encoded as a PPN.
  - `txdoc:VM-1-AUTHORITATIVE-BINDINGS-AND-MATERIALIZATIONS-IN-VM`:
    `VmEntry` recipes are authoritative; PTEs are derived.
  - `txdoc:VM-3-RANGELOCK`: `RangeLock` is VM-local coordination for declared
    ranges; it does not replace pmap or PageContainer page-level publication.
- `docs/design/01_substrate/PAGE_SUBSTRATE_v1.md`
  - `txdoc:PAGE-SUBSTRATE-ZONE-DERIVED-TYPE-POLICY-1`: physical frames are
    `FrameMeta` plus typed contributors, not semantic zone entities.
  - `txdoc:PAGE-SUBSTRATE-FRAMEMETA-CAS-DISCIPLINE-1`: liveness is packed
    counter evidence; token drop decrements the relevant role.
- `docs/design/03_memory-vm/PAGE_BACKED_v1.md`
  - `txdoc:PAGE-BACKED-ADDRESS-BOUNDARY-POLICY`: PageBacked speaks
    `Cap<PageContainer>`, page indexes, byte offsets, and frame role evidence;
    raw address arithmetic stays at VM/page-substrate handoff points.
  - splice section: pipe owns ordered waitable transport; PageBacked owns page
    leases and install/copy fallback.
- `docs/progress/decisions/2026-05-24-pipe-lease-ring-policy.md`
  - Pipe stores descriptor slots; PageBacked owns `PageLease` creation,
    retain/release evidence, and destination install/copy policy.
  - Current blocker: `SPLICE_F_GIFT` needs VM user-page pin/adoption/freeze and
    release ownership transfer.

## Scope

In scope:

- Active-doc amendment for user-page gift vocabulary and obligations.
- Substrate typed frame evidence for long-lived transfer through pipe
  descriptors.
- VM-owned `UserPageGift` / `GiftBatch` values and gift step.
- PageBacked install/copy consumption of `UserPageGift`.
- Pipe descriptor storage and transfer of `UserPageGift`.
- `vmsplice(SPLICE_F_GIFT)` syscall path using the gift operation when safe,
  falling back to byte copy for unsupported cases.
- Targeted unit tests and splice/vmsplice shim tests.

Out of scope:

- Replacing VM recipes with page-granular authoritative bindings.
- A generic page subsystem or page object lock.
- Device/MMIO page gifting.
- Shared writable mapping stealing in the first slice.
- Partial-page gift tokens in the first slice.
- Memory pressure reclaim policy.
- Broad OSComp scoring cleanup beyond validating the new path.

## Public Vocabulary

Use these names unless the active-doc amendment chooses a better spelling:

```rust
pub struct UserPageGift {
    ppn: Ppn,
    source: UserPageGiftSource,
    pin: GiftPin<'static, BitmapPageAllocator<'static>>,
    freeze: UserPageGiftFreeze,
}

pub struct GiftBatch {
    gifts: Vec<UserPageGift>,
    bytes: usize,
}

pub struct UserPageGiftSource {
    aspace: Cap<AddressSpace>,
    range: UserRange,
}

pub enum UserPageGiftFreeze {
    DetachedPrivate,
    DemotedCow,
}
```

The exact field visibility should stay private to VM. Pipe and PageBacked need
accessor methods such as `ppn()`, `len()`, and a consuming install method; they
should not mutate freeze state.

## Design Decisions To Settle First

1. `GiftPin` backing counter:
   - Preferred first slice: use a new substrate role token backed by a widened
     long-lived transfer counter if the packed `pin_count` is too narrow for
     pipe queues and `tee`.
   - Acceptable staging if no counter layout change is wanted immediately:
     a retained-frame token on the generic `refcount`, explicitly documented as
     transfer evidence rather than DMA evidence.
   - Do not reuse `DmaPin` semantically; DMA and IPC transfer have different
     lifetimes and pressure profiles.
2. Eligible source mappings in v1:
   - Full-page aligned iovec segments only.
   - Private anonymous and private CoW pages first.
   - PageBacked MAP_PRIVATE after materialization is acceptable if the result
     is a private frame.
   - MAP_SHARED, device mappings, and unaligned head/tail ranges use copy
     fallback.
3. Freeze behavior:
   - Release of a gift token does not restore the old writable PTE.
   - Freeze means VM has removed or demoted user writable ownership before the
     token is published to pipe.
   - Future writes refault and get a fresh private page through existing CoW
     machinery.

## Readiness

Ready: mostly for implementation after Task 1 lands.

Blocking gaps:

- Active docs do not yet define `UserPageGift` or `GiftPin` as current
  vocabulary.
- Substrate counter choice is unresolved: `DmaPin` is the wrong semantic role,
  and the current packed `pin_count` may be too narrow for long-lived pipe
  descriptors plus `tee`.
- Current pmap helpers tear down ranges but do not expose a focused
  remove/demote-and-return-transfer-evidence operation.

Nonblocking follow-ups:

- Partial-page gift tokens can wait; copy unaligned heads/tails.
- MAP_SHARED stealing can wait; copy fallback is correct.
- Watchqueue/notification pipes remain a separate pipe mode.

Implementation entry order:

1. Task 1 active-doc amendment.
2. Task 2 substrate evidence.
3. Task 3 and Task 4 VM token/step.
4. Task 5 PageBacked consumption.
5. Task 6 pipe descriptor storage.
6. Task 7 and Task 8 syscall/end-to-end integration.
7. Task 9 and Task 10 verification/observability.
