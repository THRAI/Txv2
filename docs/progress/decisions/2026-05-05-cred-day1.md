# Cred service stub day-1

**Date:** 2026-05-05
**Branch:** `process-topology` (continued from signal day-1)
**Status:** Complete. CI green (11 gates). 11 new cred tests pass; total suite 227.

## Goal

Plug the credential service into `ProcessPayload` so future
permission-checking code (signal kill semantics, exec, fork-with-cred,
file access checks) has a real cred field to consult. Day-1 covers
identity (`uid`, `euid`, `gid`, `egid`), capability bitset, and
`setuid` / `setgid` privilege semantics. Saved-set IDs, supplementary
groups, fsuid/fsgid, and the bounding / inheritable / ambient
capability sets are deliberately deferred — they extend the existing
`Cred` shape rather than reshape it.

## What landed

### Module

```

crates/tx-subsystems/src/cred/tests.rs  11 tests
```

`cred.rs` lives next to other tx-subsystems modules. Per

`ProcessPayload`.

### Types

| Type | Notes |
|---|---|
| `Uid(u32)` | `Uid::ROOT` = 0; `is_root()` helper. |
| `Gid(u32)` | Same shape. |
| `Capability(u8)` | Bit position; constants `CHOWN`, `DAC_OVERRIDE`, `KILL`, `SETGID`, `SETUID`, `NET_ADMIN`, `SYS_ADMIN`. |
| `CapabilitySet(u64)` | Bitset; `EMPTY`, `FULL`, `add` / `remove` / `contains`. |
| `Cred` | `{uid, euid, gid, egid, effective_caps, permitted_caps}`. `Copy`, `Default`. |

`Cred::root()` constructs the privileged cred used at boot. `Cred`
exposes `is_privileged_for(cap)` (`euid.is_root() || effective_caps.contains(cap)`)
and `shares_euid(other)` for the future signal-permission check.

### State on `ProcessPayload`

```rust
pub struct ProcessPayload {
    aspace, threads, sig_actions, group_pending,  // (existing)
    cred: SpinMutex<Cred>,                        // NEW
}
```

`ProcessPayload::cred()` accessor returns a `Copy` (one lock
acquisition per snapshot read). Mutators
(`cred::step_setuid` / `step_setgid`) take the lock internally.

### Bootstrap + fork wiring

| Path | Behavior |
|---|---|
| `bootstrap_init_process(aspace)` | Initializes `cred = Cred::root()`. |
| `step_fork(parent)` | Snapshots `parent.cred()` and passes it to the child's `sign_process_payload`. The child's cred is a fresh independent `Cred` value (no aliasing). |

`sign_process_payload` now takes a `cred: Cred` parameter alongside
`aspace` and `threads`.

### Mutators

| Function | Privileged behavior | Non-privileged behavior |
|---|---|---|
| `step_setuid(target, new_uid)` | sets both `uid` and `euid` to `new_uid` | only allowed if `new_uid` matches existing `uid` or `euid`; otherwise `PermissionDenied` |
| `step_setgid(target, new_gid)` | sets both `gid` and `egid` to `new_gid` | same swap-among-existing rule |

Both return `CredChange::Replaced { prev, new }`,
`CredChange::PermissionDenied`, or `CredChange::Zombie` (target had
no payload).

## Deliberately deferred

- **Saved-set IDs** (`suid`, `sgid`). Required for `setresuid`-family;
  the day-1 simplified rule "non-privileged setuid only swaps among
  `(uid, euid)`" approximates the saved-id behavior without storing it.
- **`fsuid` / `fsgid`**. Linux-specific filesystem-uid distinction.
- **Supplementary groups list**. POSIX requires a bounded `Vec<Gid>`;
  day-1 elides it. Adds when access-check code needs it.
- **Capability bounding / inheritable / ambient sets**. Day-1 carries
  only `effective_caps` and `permitted_caps`.
- **`step_setresuid`, `step_setreuid`, `step_capset`,
  `step_seteuid`, `step_setfsuid`**. Land alongside the syscall
  scripts that drive them.
- **Permission checks**. `step_kill_process` / `step_kill_pgrp`
  currently route signals without consulting cred. The check
  (`source.shares_euid(target) || source.is_privileged_for(KILL)`)
  lives in the shim once a real syscall driver invokes `kill` from a
  caller cred.
- **Migration to a dedicated cred-service crate**. Mechanical follow-up.
