## What landed

Five outputs, all red→green TDD:

1. **Baseline doc**
   [`docs/progress/decisions/2026-05-09-v3-baseline.md`](2026-05-09-v3-baseline.md)
   locks the workspace at **1152 passed / 0 failed / 4 ignored across 47
   binaries** captured via `cargo test --workspace --lib --tests --
   --test-threads=1`.

2. **v3 step algebra stub**
   `crates/tx-substrate/src/step_v3.rs` introduces the v3 step shape:
   `StepOutcome` four-variant (Done / Advanced / Yield / Err),
   `YieldShape::OnCarrier`, the `StepProgress` trait with `NoProgress`
   and `ByteProgress` impls, `DriveMode` + `classify`, `AcceptOutcome`,
   `Translation`, and `Errno::EAGAIN`. Pinned by 15 tests in
   `crates/tx-substrate/tests/v3_algebra.rs` and 5 StepOp tests in
   `crates/tx-substrate/tests/v3_step_op.rs` (the StepOp trait + an
   empty placeholder `ScriptCtx` shipped together with the algebra
   stub). Module wired in `crates/tx-substrate/src/lib.rs`.

3. **A-3 anti-pattern lint**
   `xtask/src/lint.rs` gains the `lint_step_no_await` helper —
   single-pass character walk so a same-line `fn step() { x.await }`
   body is detected as cleanly as a multi-line one — and four pin
   tests:
   - `arch_lint_rejects_await_in_step_fn_body`
   - `arch_lint_rejects_await_in_same_line_step_fn_body`
   - `arch_lint_allows_await_outside_step_fn`
   - `arch_lint_allows_step_underscore_named_fn_with_await`

4. **txdoc-Txv3 harvest**
   `xtask/src/lint.rs` extends `lint_docs` with two new helpers
   (`extract_txv3_code_references`, `lint_txv3_code_references`) and a
   second pass after the markdown harvest: every Rust source under
   `crates/`, `boards/`, and `xtask/` is scanned for
   `txdoc:TXV3-*` references in `//`, `///`, and `//!` comments;
   each reference must resolve to a tag declared in some
   `docs/Txv3/` (or `docs/design/`) markdown. Three pin tests:
   - `docs_lint_accepts_code_reference_to_known_txv3_tag`
   - `docs_lint_rejects_code_reference_to_unknown_txv3_tag`
   - `docs_lint_treats_code_reference_to_v4_design_tag_as_already_supported_or_explicit_pass`

   Carveouts: wildcard tag fragments (e.g. the bare `TXV3-` suffix
   from prose like `txdoc:TXV3-*`) are not flagged, and
   `xtask/src/lint.rs` itself is excluded from the real-file pass
   (the linter must describe its own pattern and contains test
   fixtures by necessity).

5. **STATUS.md catch-up**
   [`docs/progress/STATUS.md`](../STATUS.md) gains a 2026-05-09 PR-0
   entry summarizing the above and pointing forward to PR-1.

## Real signal: unresolved txdoc references in code

Running `cargo xtask lint docs` against the live repo surfaces three
unresolved `txdoc:TXV3-*` references in `crates/tx-substrate/src/step_v3.rs`:

```
crates/tx-substrate/src/step_v3.rs:18: code references unknown txdoc tag `TXV3-STEP-MODEL-V2-STEP-1`
crates/tx-substrate/src/step_v3.rs:19: code references unknown txdoc tag `TXV3-STEP-MODEL-V2-STEP-3`
crates/tx-substrate/src/step_v3.rs:20: code references unknown txdoc tag `TXV3-STEP-MODEL-V2-YIELD-1`
```

`docs/Txv3/03_STEP_MODEL_v2.md` declares the file-level
`TXV3-STEP-MODEL-V2` plus a flat catalog of `STEP-V2-…` section anchors
(`STEP-V2-PRIMITIVE-1`, `STEP-V2-OUTCOME-ALGEBRA-1`,
`STEP-V2-PROGRESS-TYPED-1`, `STEP-V2-YIELD-SHAPE-1`, …). The author of
`step_v3.rs` evidently expected a hierarchical
`TXV3-STEP-MODEL-V2-STEP-1` naming. PR-0 reports this without fixing —
`crates/tx-substrate/` is the parallel agent's write-scope. Resolution
options for PR-1 (or a follow-up):

- **Rename in code** to match the markdown anchors (`STEP-V2-OUTCOME-ALGEBRA-1`
  for STEP-1, `STEP-V2-PROGRESS-TYPED-1` for STEP-3, `STEP-V2-YIELD-SHAPE-1`
  for YIELD-1).
- **Add anchors in markdown** under the hierarchical naming the code
  uses.
- **Both** — depending on which set is canonical for downstream
  consumers.

PR-0 cannot land `cargo xtask lint docs` as a CI gate until this is
reconciled; the integration commit should either (a) reconcile the
names or (b) park the new harvest behind a follow-up gate. This is the
primary integration item I am flagging for the parent agent.

  tuples to `lint_txv3_code_references`. This makes the unit tests
  hermetic without `tempfile`, which keeps the dev-dep surface flat.
