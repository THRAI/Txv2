# Signal day-1 (post + observe)

**Date:** 2026-05-05
**Branch:** `process-topology` (continued from topology day-1)
**Status:** Complete. CI green (11 gates). 13 new signal tests pass; total suite 216.

## Goal

Layer the signal state and POSIX shims on top of the day-1
process/thread topology so that subsequent passes (AST delivery, default
disposition resolution, realtime queueing, SigInfo) extend the existing
fields rather than reshape them.

This pass deliberately stops at "post + observe": kill enqueues, mask
hides, sigaction installs disposition. No actual delivery. The reactor
AST + script integration that consumes pending bits and invokes
handlers lands later.

`signal.rs` lives next to other tx-subsystems modules rather than as
its own crate. Per `MODULE_MAP_v1` §11 the formal home is
`crates/tx-shims/posix_signal/`; for day-1 we keep it co-located so
the shim can call `pub(crate)` accessors on the per-process /
per-thread state. The migration to a separate crate is a mechanical
follow-up once cred / rlimit services land and the shim has more to do.

### Types

| Type | Shape | Notes |
|---|---|---|
| `Signum(u8)` | 1..=64 | `SIGHUP`/`SIGINT`/`SIGTERM`/`SIGKILL`/`SIGSTOP`/etc. constants. `is_uncatchable()` = SIGKILL or SIGSTOP. |
| `SignalMask(u64)` | bitset, bit i = signum i+1 blocked | `new` strips uncatchable bits; `block` is a no-op for SIGKILL/SIGSTOP. |
| `PendingSignalQueue` | `AtomicU64` bitset | Day-1 collapses repeated posts of the same standard signal. RT per-occurrence queueing is a follow-up. |
| `SigDisposition` | `Default` / `Ignore` / `Handler(usize)` | `Handler` carries an opaque address; resolution happens at the (future) delivery step. |
| `SigActionTable` | `[SigDisposition; 64]` under SpinMutex | `set` is a no-op for uncatchable signums, preserving POSIX. |

### State on existing entities

```rust
ProcessPayload {
    aspace, threads,                  // (existing topology fields)
    sig_actions: SigActionTable,      // NEW — per-process disposition table
    group_pending: PendingSignalQueue,// NEW — process-group-targeted queue
}

ThreadPayload {
    task,                             // (existing reactor placeholder)
    signal_mask: AtomicU64,           // NEW — atomic bitset
    thread_pending: PendingSignalQueue,// NEW — per-thread queue
}
```

### Shim entry points

| Function | Behavior |
|---|---|
| `signal::step_kill_process(target, sig)` | Routes to first live thread; posts to `thread_pending`. Returns `KillOutcome::Delivered` or `NoLiveThread` (zombie skip). |
| `signal::step_kill_pgrp(pgrp, sig)` | Walks `pgrp.members`, calls `step_kill_process` per live member. Mirrors onto each delivered process's `group_pending` so the (future) delivery step can distinguish thread-targeted vs group-targeted posts. Returns delivered count. |
| `signal::step_sigaction(process, sig, disp)` | Installs disposition in `sig_actions`. Returns `Replaced { prev }` / `Uncatchable(prev)` / `ZombieIgnored`. |
| `thread_runtime::execution::step_sigprocmask(thread, how, next)` | `SetMask` / `Block` / `Unblock`. Returns `Replaced { prev, new }` or `ZombieIgnored`. Strips uncatchable bits. |
| `thread_runtime::execution::post_signal(thread, sig)` | Internal helper used by the kill shim; pub for clarity. |

## Deliberately deferred

- **SigInfo payload** (`si_code`, `si_value`, `si_pid`, `si_uid`,
  `si_status`). Day-1 carries only the signum bit; queue is a bitset.
- **Realtime per-occurrence queueing** (signums 32..=64). Bits coexist
  with standard signals but multiple posts collapse.
- **Default-disposition resolution** (Default → terminate / stop /
  continue / ignore). `SigDisposition::Default` is recorded but the
  delivery step that interprets it is not yet wired.
- **AST / handler invocation**. There is no signal-delivery step yet:
  bits sit in `thread_pending` / `group_pending` indefinitely until
  the reactor / scripts pass introduces a sweep + frame-build path.
- **SIGSTOP / SIGCONT semantics on stop_state**. Topology has no
  stopped-thread state machine yet.
- **Numeric `step_kill(pid_t)`**. No pid → process registry; callers
  pass `Cap<ProcessIdentity>`. Numeric kill lands when the registry
  does (typically alongside the scripts pass).
- **TTY job control activation**. `TtyIdentity.session_pgrp` triplet
  still holds raw IDs. Once it rebinds to `Weak<Session>` /
  `Weak<ProcessGroup>` (small follow-up) and the delivery step exists,
  TIOCSCTTY/SIGTTIN/SIGTTOU paths can fire `step_kill_pgrp`.
- **`signalfd`, `pidfd_send_signal`, `tgkill`**. Rely on AST delivery.
- **Migration to `crates/tx-shims/posix_signal/`**. Mechanical; the
  shim is presently co-located.

## Next step

Once the topology + signal day-1 lands as a merged PR, the natural
order is:

1. **TTY pgrp typed-rebinding**: change `TtyIdentity.session_pgrp` raw-id
   triplet to typed `Weak<Session>` / `Weak<ProcessGroup>`. Required
   before signal job control fanout can hit the right pgrp. ~1 session.
2. **Signal delivery step (β-deliver)**: introduce the reactor-side
   sweep that consults `signal_mask`, `pending`, and `sig_actions` to
   resolve a deliverable signal, build a frame, and either invoke a
   handler or apply the default action. Activates SigDisposition.
   ~2 sessions.
3. **Cred / rlimit services (β-cred / β-rlim)**: small synchronous
   services feeding `cred: CredSnapshotRef` / `rlimits: RLimitBagRef`
   onto `ProcessPayload`. Required for `step_clone3` and `step_execve`.
   ~1–2 sessions.
4. **Boot wiring**: thread `bootstrap_init_process` through
   `tx-kernel/src/init.rs` so the kernel actually has a pid=1 at
   runtime. ~1 session.
