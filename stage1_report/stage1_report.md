# 内核赛初赛技术报告

## 前言：内核对用户的契约

### 1.1 内核执行语义

第一段：总述
> 从用户态进程的角度看，内核暴露的不是内部对象本身，而是一组可被稳定引用、观察和驱动的资源与能力。第一类是资源访问能力：进程通过用户可见标识引用内核对象，例如进程号、文件描述符、路径、虚拟地址、设备节点和系统调用参数中的对象句柄。第二类是进程协作与内核通知能力：内核围绕阻塞、唤醒、异步通知和调度抢占，向进程提供等待、同步、取消、终止和事件分发机制。第三类是操作执行语义：系统调用把这些用户可见标识解析为当前进程有权访问的内核对象，并以 Linux 规定的方式执行状态转移、提交结果、返回错误码或部分完成结果。

这里先不直接用 signifier，避免一上来引入 Tx 术语。
第二段：用户可见标识 / 资源暴露
> 内核内部维护 task、地址空间、文件表、VMA、open file、inode、wait queue、signal queue 等权威状态；用户态不能直接访问这些状态，只能通过用户可见标识间接引用它们。路径指向文件系统命名空间中的对象，fd 指向进程文件表中的 open file，pid/tid 指向进程或线程身份，虚拟地址指向地址空间中的 VMA 和页表映射，设备节点和 ioctl 参数则把设备能力暴露为统一接口。系统调用首先要完成的事情，通常就是在当前进程身份、权限和 namespace 视图下解析这些标识，并判断调用者是否有权继续操作。

第三段：通信 / 阻塞 / 通知
> 进程之间以及进程与内核之间还需要协作。Linux 并没有把这种协作归约为单一 IPC，而是提供了一组围绕中断、阻塞、信号、资源共享建立的机制：阻塞表示当前操作需要等待外部条件，唤醒表示条件可能已经改变，异步通知用于把控制事件投递给目标 task，调度抢占则保证执行权可以被内核重新分配。信号负责异步控制和异常传播，wait/waitpid 负责父子生命周期观察，futex 支撑 pthread mutex/condvar 等用户态同步，pipe/socket/device I/O 提供数据通道，fd readiness 与 poll/epoll 则把不同对象的可继续执行状态统一成可等待事件。

然后接现代 fd-poll 模型：
> 现代 Linux 的 fd/poll 模型可以看作“用户可见标识 + 通知能力”的结合。普通文件、目录、设备、pipe、socket 原本就以 fd 暴露；eventfd、signalfd、timerfd、pidfd、userfaultfd 和 epoll fd 进一步把事件、信号、定时器、进程身份、缺页通知和 readiness 集合也纳入 fd 体系。于是 fd 不只是“文件句柄”，而成为一种可关闭、可传递、可等待、可复用的内核对象引用；poll/epoll 则成为跨对象类型的通知汇聚机制。

第四段：执行语义
> 在资源标识和通知机制之内，是系统调用自身的执行语义。一次 syscall 通常包含三个阶段：解析用户可见标识，执行一个或多个有边界的内核状态转移，在明确的可见性边界上发布结果。这里的“有边界”不等于数据库式事务；Linux 允许部分完成，例如 partial read/write，也允许阻塞 I/O 被信号打断后按进度返回或返回 EINTR。但内核仍必须维护一致性：未提交的中间状态不能泄露，已经提交的可见状态必须能被之后的查询、等待、信号和文件描述符操作一致地观察到。

最后引出 Tx 概念：
> 因此，内核的核心功能可以概括为三件事：第一，维护用户可见标识到内核对象的稳定解析；第二，提供阻塞、唤醒、异步通知和抢占构成的协作机制；第三，定义系统调用的执行、提交、失败和部分完成语义。后文将把第一类用户可见标识统一称为 signifier，把“谁在发起操作”的上下文称为 SubjectContext，把有边界的状态转移称为 StepOp，把可等待点称为 YieldShape，把返回值、唤醒、信号和 /proc 等可见结果称为 Publication/Projection。
